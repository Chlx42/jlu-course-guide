# 课程资料页重构说明

## 问题诊断

### 原有页面的问题

1. **内容空洞**：大量"待补充"占位符，实际可用信息极少
2. **资料堆砌**：只是罗列 GitHub 链接，没有分类和使用指导
3. **缺少实战指导**：没有学习路线、避坑指南、考试攻略
4. **视觉平淡**：纯文本列表，信息层级不清晰

### 原有页面示例（数据结构）

```markdown
## 课程信息
- **课程代码**: 542003
- **学分**: 4
- 难度: ⭐⭐⭐ (3/5)

## 资料链接
- [数据结构](链接)
- [上机](链接)

## 学习建议
- 待补充
```

**问题**：
- 没有告诉学生"这门课到底怎么学"
- 资料链接没有说明哪个最重要、怎么用
- 缺少学长学姐的真实经验

## 第一性原理重构

### 核心原则

**从用户根本需求出发**：

1. **快速评估**：这门课难不难？值不值得重视？
2. **资料定位**：我需要什么资料？在哪找？
3. **学习路径**：从零基础到考试通过，每一步怎么走？
4. **避坑指南**：前人踩过哪些坑？如何避免？
5. **实战经验**：学长学姐怎么说？真实反馈是什么？

### 新版页面结构

```
📌 课程速览（3秒评估）
├─ 视觉化卡片：课程代码、学期、通过率
├─ 一句话总结：这门课是什么
└─ 难度标签

📥 资料速查（分级引导）
├─ 🎯 核心资料（必看）：往年题、PPT、代码模板
├─ 📚 拓展资源（提高）：经典教材、在线课程
└─ 每个资料附说明：干什么用的

📖 课程内容（知识地图）
├─ ASCII 树状图：知识结构一目了然
├─ 重难点拆解表：难度+考试占比+学习建议
└─ 不是照抄教学大纲，而是学生视角的知识图

💡 学习路线（分阶段执行）
├─ 阶段一：打基础（Week 1-6）
├─ 阶段二：刷题强化（Week 7-12）
├─ 阶段三：考前冲刺（考前2周）
└─ 每阶段有明确任务清单和 Tips

⚠️ 常见陷阱（血泪教训）
├─ 真实翻车案例
├─ ❌ 错误做法 + 💥 后果
└─ ✅ 正确做法

📝 考试攻略（应试技巧）
├─ 题型分布表
├─ 高频考点（分送分题/拉分题）
├─ 答题策略
└─ 时间分配建议

💬 学长学姐说（真实反馈）
├─ 带年级+专业标签
├─ 具体场景+具体建议
└─ 不是泛泛而谈，而是可操作的经验

📊 数据统计（收起展开）
├─ 平均分、优秀率、挂科率
└─ 周均学时
```

## 重构成果展示

### 1. 数据结构页面

**特色设计**：

- **渐变卡片**：课程代码、开课学期、通过率用渐变色卡片展示
- **知识地图**：ASCII 树状图清晰展示线性结构、树、图的占比
- **三阶段学习路线**：
  - Week 1-6 打基础（跟课+手写代码）
  - Week 7-12 刷题（LeetCode 链表10-15题、树15-20题）
  - 考前2周冲刺（往年题+错题本+手写高频代码）
- **5大陷阱**：光看不练、指针操作翻车、递归理解不透、PTA抄答案、考前突击
- **课程设计指导**：三选一题目类型、高分要点（60/70/85/95分档）

**页面路径**：`content/courses/data-structure.md`

### 2. 编译原理页面

**特色设计**：

- **硬核定位**：用"🔥吉大计院最硬核课程"明确预期
- **大作业耗时卡片**：40-80小时，让学生提前规划
- **编译器全流程图**：ASCII 框图展示从词法到目标代码的完整流程
- **6周开发计划**：
  - Week 1-2 词法+语法（任务清单+避坑指南）
  - Week 3-4 语义分析（符号表数据结构示例）
  - Week 5 中间代码（三地址码示例）
  - Week 6 目标代码+测试
- **技术选型表**：C++/Java/Python/Rust 四维对比（开发速度/性能/调试难度/推荐指数）
- **血泪教训**：6个真实翻车案例（拖延症、完美主义、闭门造车、测试不足、版本混乱、死记硬背）
- **往届实现精选**：14个项目按语言分类折叠展示

**页面路径**：`content/courses/compiler.md`

## 设计细节

### 视觉设计

**配色方案**（遵循 design_sense）：

- **数据结构**：紫色系（理性、结构化）
  - `#667eea → #764ba2`（课程代码）
  - `#f093fb → #f5576c`（开课学期）
  - `#4facfe → #00f2fe`（通过率）

- **编译原理**：橙红色系（硬核、挑战）
  - `#fa709a → #fee140`（课程代码）
  - `#ff6a00 → #ee0979`（开课学期）
  - `#f12711 → #f5af19`（大作业耗时）

**排版原则**：

- CSS Grid 布局，响应式卡片
- 圆角 `12px`，内边距 `1.25rem`
- 渐变背景用 `135deg` 斜向
- 字体大小流式缩放（标题 `1.5rem`，副标题 `0.875rem`）

### 内容设计

**写作原则**：

1. **具体>抽象**："刷 LeetCode 链表 10-15 题" > "多练习"
2. **场景化**："最后一周通宵爆肝，代码一团乱麻" > "不要拖延"
3. **可操作**："提前4周启动，每周固定时间开发" > "尽早开始"
4. **真实反馈**：学长学姐的话带年级+专业+具体分数
5. **避坑为主**：用 ❌ 错误做法 + 💥 后果 + ✅ 正确做法 三段式

**信息密度**：

- 原版：~50 行，80% 是占位符
- 新版：~260 行（数据结构）、~400 行（编译原理），100% 实用信息

## 总结

通过从第一性原理重新思考"学生真正需要什么"，我们将课程资料页从**信息目录**转变为**学习指南**：

- **不只是"资料在哪"**，而是"资料怎么用"
- **不只是"课程讲什么"**，而是"怎么学才能过"
- **不只是"考试考什么"**，而是"怎么答才能拿高分"
- **不只是"官方说明"**，而是"学长学姐真实经验"

这才是真正对学生有用的课程攻略。
